## Этап 1. Коллекции и Stream API на примере Book (задание на паре)

Использованная нейросеть: Gigachat

**Промпт:**
> Вот описание лабораторной №4 (Lab4.md): коллекции List, Set, Map и Stream API. Сделай основное задание на классе Book: список из 10 книг, сортировка по году (Collections.sort + Comparator) и по автору, фильтрация после 2000 года; Set<Book> с переопределёнными equals() и hashCode() и проверкой дубликатов; Map<String, List<Book>> с группировкой по автору; примеры Stream API (filter, map, sorted, groupingBy); замер времени поиска в ArrayList и HashSet для 100 000 элементов. Java 17+, Javadoc.

**Результат ИИ:** ассистент сгенерировал класс `Book` с `equals()` и `hashCode()` (по названию, автору и году, через `Objects.equals` и `Objects.hash`), класс `BookDemo` с четырьмя демонстрациями (List, Set, Map, Stream API) и вспомогательный класс `CollectionBenchmark` для замера времени. В `Main` вызывается `BookDemo`.

**Анализ результата:**
- `equals()` и `hashCode()` строятся по одним и тем же полям; идентификатор в них не входит, поэтому книга с тем же названием, автором и годом, но другим id считается дубликатом и в `Set` не добавляется. [ПРОВЕРИТЬ: в выводе «Дубликат добавлен: false».]
- Сортировка по автору дополнена вторым критерием (`thenComparing`), чтобы порядок книг одного автора был предсказуемым.
- Замер показывает, что поиск в `HashSet` на порядки быстрее, чем в `ArrayList` (поиск по хеш-коду против перебора). Точные цифры зависят от компьютера. [ПРОВЕРИТЬ и вставить свои значения.]
- Для замера выполняется «прогревочный» прогон, чтобы результат не искажала работа JIT-компилятора.

**Внесённые изменения:** создан проект `lab04-collections`, код перенесён в пакеты `com.university.lab04.model`, `service` и `util`. [ДОПИСАТЬ, если что-то меняла сама.]

## Этап 2. Индивидуальное задание (вариант 2, Employee)

Использованная нейросеть: Gigachat
**Промпт:**
> Мой вариант — 2, класс «Сотрудник» (id, fullName, position, department, salary). Сделай: список из 10 сотрудников и три вида сортировки (по ФИО, по должности, по зарплате), Set с equals()/hashCode(), группировку по отделу, фильтрацию зарплаты > 100000, среднюю зарплату по отделам через Stream API и замер производительности ArrayList и HashSet.

**Результат ИИ:** написаны класс `Employee` с `equals()` и `hashCode()` и класс `EmployeeDemo`: три сортировки (в том числе по должности с последующей сортировкой по ФИО и по зарплате по убыванию), проверка дубликатов, группировка по отделу, фильтрация и `Collectors.averagingDouble` для средней зарплаты по отделам.

**Анализ результата:**
- Требования индивидуального задания выполнены: три сортировки, `Set`, группировка по отделу, фильтрация > 100000, агрегация по отделам, замер.
- Средняя зарплата по отделам проверена вручную: отдел данных — (95000 + 105000 + 150000) / 3 = 116666.67; отдел качества — (80000 + 85000 + 45000) / 3 = 70000.00; отдел разработки — (120000 + 180000 + 110000 + 50000) / 4 = 115000.00. [ПРОВЕРИТЬ после запуска.]
- Для вывода групп использован `TreeMap`, чтобы порядок отделов был алфавитным и результат запуска повторялся.

**Внесённые изменения:** добавлены `Employee.java`, `EmployeeDemo.java`, расширен `Main`. [ДОПИСАТЬ.]
